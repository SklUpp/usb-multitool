# USB Multitool

**Русский** | [English](README.en.md)

Android-приложение для работы с USB-накопителями напрямую: файлы, разделы MBR/GPT, форматирование FAT/exFAT/NTFS/EXT4, запись образов, установка Ventoy и диагностика диска без root.

Проект распространяется как sideload-APK, лицензия приложения — `GPL-3.0-or-later`. Интерфейс — на английском и русском, переключатель языка находится в приложении.

## Что это

Приложение работает с USB mass-storage устройством через Android USB Host API (`UsbDeviceConnection` + Bulk-Only Transport/SCSI). Файловые системы открываются собственными движками на C через JNI, а не через Android-монтирование; Storage Access Framework используется только для выбора файлов на телефоне (импорт, экспорт, образы для восстановления).

Строки интерфейса живут в ресурсах: английский — по умолчанию, русский — в `values-ru`. Выбор языка «Система / Русский / English» сохраняется между запусками.

Раскладка репозитория:

| Путь | Содержимое |
| --- | --- |
| `usb-multitool/app/` | Kotlin/Compose-приложение и JNI-мосты |
| `usb-multitool/app/src/main/cpp/` | движки FAT/exFAT, NTFS, EXT4 и адаптер блочного устройства |
| `usb-multitool/scripts/` | загрузка закреплённых upstream-исходников, host-тесты и проверка выравнивания APK |
| `usb-multitool/third_party/` | исходники и уведомления сторонних компонентов |
| `.github/workflows/android-debug.yml` | единственное место, где выполняются Gradle/NDK-сборки |

## Возможности

Интерфейс — четыре вкладки: **Файлы**, **Ventoy**, **Разделы**, **Диагностика**. Ниже перечислено только то, что реализовано в текущей ветке.

### Файлы

- Отдельная вкладка на каждый распознанный раздел, включая EFI/VTOYEFI.
- Просмотр каталогов, создание папок, загрузка файлов с телефона (SAF), сохранение файлов на телефон (SAF), удаление и переименование.
- EFI/VTOYEFI разделы защищены от записи. Разблокировка включается для конкретного раздела и действует только в текущем подключении; она снимается при смене диска, переподключении или отсоединении. Разблокированный раздел можно также удалить или форматировать.
- Для `.iso` на накопителе: «В raw» (подготовка образа во внутреннем каталоге приложения и запись на диск) и «XML» (связывание ISO с шаблоном `autounattend.xml` Windows).

### Ventoy

- Установка и обновление сначала берут набор из `/sdcard/ventoy`, если такой каталог есть, иначе — встроенные ассеты Ventoy 1.1.18. Внешний `sha256.txt` заменяет закреплённые ожидаемые хеши для этого каталога; встроенные ассеты сверяются с закреплёнными в коде SHA-256.
- Обновление с сохранением ISO-раздела; для нераспознанной раскладки обновление отказывает.
- «Скачать новую версию и установить»: приложение запрашивает последний релиз через GitHub API. SHA-256 архива берётся из метаданных ассета GitHub, релиз без `digest` отклоняется. Для версий 1.1.05 и 1.1.18 дополнительно закреплены дайджест архива и хеши членов архива.
- Параметры Windows — три состояния. Проверки Windows 11 (`VTOY_WIN11_BYPASS_CHECK`): сохранить как есть, обойти все (TPM, RAM, Secure Boot, CPU) или требовать все. Учётная запись (`VTOY_WIN11_BYPASS_NRO`): сохранить, локальная или Microsoft. Явный выбор пишет `1` или `0`, «сохранить» не меняет существующее значение. Локальная запись требует отключённой сети при установке.
- XML-шаблон минимальный, без LabConfig и FirstLogonCommands. Существующая конфигурация перезаписывается только по явному подтверждению.

### Разделы

- Чтение MBR и GPT, отображение свободных областей и карты диска.
- Создание раздела в свободной области (выравнивание 1 MiB) и удаление раздела; MBR и GPT.
- Инициализация пустой таблицы MBR или GPT и замена текущей схемы. Подтверждение фиксирует текущую схему и геометрию всех разделов; изменение раскладки отменяет запись. Hybrid/неоднозначная раскладка и GPT, восстановленная из резервной копии, отклоняются. MBR отклоняется, если диск превышает 32-бит LBA. В GPT при создании можно задать имя раздела (до 36 символов UTF-16) и сразу отформатировать новый диапазон выбранной ФС с меткой тома. В MBR поля имени нет, поэтому имя отклоняется, а не теряется.
- Переименование GPT-имени выбранного раздела и метки тома отформатированного раздела. Переименование защищённого EFI/VTOYEFI запрещено. Метки пишут только движки, которые это умеют: FAT/FAT32 (11 символов), exFAT (11 символов), NTFS (128 символов); метка EXT4 пишется только при форматировании.
- Смена роли раздела: «сделать EFI» или «сделать данными» меняет тип раздела; прежний тип автоматически не восстанавливается.
- Флаг загрузки включается и снимается отдельной операцией; для GPT он живёт в атрибутах раздела, для MBR — в boot-флаге.
- Форматирование выбранного раздела в FAT/FAT32, exFAT, NTFS или EXT4 реальными движками.
- Запись образа `.iso`, `.img`, `.gz`, `.xz` из локального файла: проверка границ и размера до записи, распаковка на лету, прогресс, отмена.
- Если primary GPT повреждён, таблица читается из backup-копии. Создание, удаление, смена роли и флага, а также починка GPT блокируются до успешного восстановления GPT из сохранённой копии.
- Запись GPT из редактора разделов (создание, удаление, роль, флаг) публикует backup-структуры первыми, затем primary, чтобы обрыв оставлял хотя бы одну целую копию с верным CRC.
- «Восстановить таблицу GPT» переносит backup к текущему концу диска. Операция отказывает при повреждённом primary, гибридной раскладке и разделах, выходящих за новую границу.
- Восстановление GPT из сохранённой копии проверяет размер, CRC, положение backup в конце диска и совпадение primary/backup.

### Диагностика

- **Самотест**: кодеки SCSI, выравнивание и свободное место, геометрия GPT, сериализация rescue-карты, контракт конфигурации Ventoy, гейты подтверждений ФС, in-memory roundtrip FatFs, при подключённом диске — проверка живого устройства.
- **Скан чтения**: проходит диск блоками по 1 MiB и уточняет битые сектора посекторно только при medium error; ничего не пишет.
- **Образ + карта**: образ всех секторов диска и map-файл собственного формата `usb-rescue-map 2` (размер сектора, число секторов, идентичность устройства, статусы диапазонов) в `Android/data/usb.multitool/files`; непрочитанные сектора остаются в карте.
- **Копия GPT**: критические сектора таблицы сохраняются отдельным файлом.
- **Стереть устройство (нули)**: запись нулей по всему диску с подтверждением.
- Восстановление образа пишет только диапазоны из карты. COPIED-диапазоны перечитываются с диска и сравниваются с образом, расхождения перезаписываются. COPY-карта с непрочитанными (NON_TRIED) секторами отклоняется; FAILED-диапазоны записываются байтами образа (обычно там нули). Размер сектора должен совпадать, карта должна помещаться на диск, полная геометрия — не обязательна. После sync и полного покрытия без FAILED-диапазонов выполняется финальная проверка восстановленного региона с повторным чтением образа.

## Безопасность данных

> ⚠️ Операции записи необратимы средствами приложения. Ошибка в раскладке, подтверждении или выборе диска уничтожает данные накопителя. Тестируйте на пустой флешке.

- Каждая разрушительная операция требует подтверждения с идентичностью устройства (модель/серийный номер) и ёмкостью; границы раздела и переполнение проверяются до записи.
- Открытые тома синхронизируются и закрываются перед изменением таблицы разделов или записью в raw.
- Wipe, создание/удаление раздела, создание с форматированием, переименование, инициализация таблицы, форматирование, RAW_WRITE, GPT repair, смена роли и флага помечают первую запись и после неё сообщают `Partial`; до первой записи результат — `Failed` или `Cancelled`. Если раздел создан, а немедленное форматирование не удалось, раздел остаётся и операция сообщает `Partial` с результатом «существует, но не отформатирован». Ventoy install/update сообщает `Partial` при сбое собственной мутации.
- При завершении процесса состояние операции не сохраняется. Автоматического продолжения после переподключения нет.
- Rescue-образ нельзя менять до конца восстановления: приложение читает его как есть, snapshot и обнаружение изменений не обещаются, правка может дать смешанные данные. Финальная сверка не доказывает неизменность источника.
- Rescue-образ остаётся плотным файлом с картой; непрочитанные сектора видны в карте, частичный образ не выдаётся за полную копию. Для rescue-копии требуется стабильный серийный номер устройства.
- Приложение не собирает телеметрию. Сеть используется только для проверки/скачивания релизов Ventoy с GitHub.

Объявленные разрешения (`usb-multitool/app/src/main/AndroidManifest.xml`):

| Разрешение | Зачем |
| --- | --- |
| `INTERNET` | проверка и скачивание релизов Ventoy |
| `POST_NOTIFICATIONS` | уведомление о длительной операции (Android 13+) |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CONNECTED_DEVICE` | работа с диском в foreground-сервисе |
| `WAKE_LOCK` | удержание CPU только на время операции |
| `MANAGE_EXTERNAL_STORAGE` | оставлено в манифесте как задел; при запуске не запрашивается, ассеты Ventoy хранятся в app-private storage, импорт/экспорт/бэкапы идут через SAF |

## Требования и совместимость

- Android 9 (API 28) и новее; `targetSdk`/`compileSdk` 36.
- Только `arm64-v8a`.
- Аппаратная поддержка USB Host (OTG) и USB mass-storage с Bulk-Only Transport. UAS и другие транспорты не поддерживаются.
- Логический размер сектора берётся у устройства, код не предполагает 512 байт. Для Ventoy диски 4K native (4096 байт) отклоняются: upstream это не поддерживает.

Совместимость с конкретными моделями флешек, OTG-переходников и хабов в репозитории не подтверждена: тесты в CI не эмулируют реальный USB. Установка Ventoy и запись ISO не гарантируют загрузку на конкретном ПК — это отдельные приёмочные проверки.

## Получение APK

Релизов и публикации в Google Play нет. Debug-APK собирается в GitHub Actions:

1. Открыть [workflow `android-debug`](../../actions/workflows/android-debug.yml).
2. Запустить его вручную (`workflow_dispatch`) или дождаться запуска по push в ветку `feature/android-usb-multitool`.
3. В артефактах запуска скачать `app-debug-apk` (там же `unit-test-reports`).

APK подписан debug-ключом и предназначен для тестирования, а не для распространения. Локальная сборка Gradle/NDK в проекте не предусмотрена — см. `usb-multitool/CONVENTIONS.md`. Этот README не подтверждает успешный финальный CI-прогон или проверку на устройствах.

## Ограничения

- Нет перемещения, сжатия и расширения занятых разделов и их файловых систем.
- F3, write-benchmark, образы по HTTP(S): не планируются.
- Нет root, FUSE, loop-устройств и UAS; нет автоматического восстановления операции после обрыва.
- CI проверяет код и host-движки, но не реальные USB-разрешения, поведение на телефоне, загрузку с флешки и установку Windows.
- Выравнивание APK и ELF под 16 KB проверяет скрипт в CI; проверки на устройстве нет.
- Отдельного файла `LICENSE` в корне пока нет: лицензия зафиксирована в коде (`usb-multitool/app/src/main/kotlin/usb/BuildFacts.kt`).

## Сборка и проверки

Все Gradle/NDK-команды выполняются только в GitHub Actions (`.github/workflows/android-debug.yml`), рабочий каталог — `usb-multitool`. Порядок шагов джобы `verify`:

```bash
./scripts/fetch-third-party.sh
./scripts/run-exfat-fsck-host-test.sh
./scripts/run-ntfs-host-test.sh
./scripts/run-ext-host-test.sh
./scripts/run-usb-block-host-test.sh
./gradlew :app:testDebugUnitTest --no-daemon
./gradlew :app:assembleDebug --no-daemon
./scripts/check-16kb-alignment.sh app/build/outputs/apk/debug/*.apk
./gradlew :app:lintDebug --no-daemon
./gradlew :app:compileDebugKotlin --no-daemon
```

`:app:testDebugUnitTest` включает и Robolectric-тесты: реальный `MainActivity` (запрос POST_NOTIFICATIONS) и SAF-границу `ImageSource.fromContentUri`. Robolectric скачивает `android-all` jar при первом запуске, поэтому нужен доступ в сеть; устройство и эмулятор не нужны.

Отдельная джоба `fatfs-host` (без Android SDK) собирает и запускает host-тесты FatFs:

```bash
make -C native-tests/fatfs test
```

Локально допустимы статические проверки: `sh -n gradlew`, `git grep` по закреплённым значениям, `sh scripts/run-ui-host-check.sh` (скрипт рассчитан на пути Termux и требует `kotlinc`). Скрипты `fetch-third-party.sh` и host-тесты скачивают и собирают upstream-исходники в `usb-multitool/third_party/` — запускать только осознанно.

| Что CI доказывает | Чего CI не доказывает |
| --- | --- |
| Компиляция Kotlin/Compose и NDK-движков, lint, unit-тесты | работу с реальным USB-накопителем и разрешения Android |
| host-тесты FatFs/exFAT/NTFS/EXT на файловых образах | загрузку Ventoy и установку Windows на ПК |
| Сборку debug-APK и проверку выравнивания под 16 KB | поведение на конкретном телефоне и флешке |

### Версии приложения

Единственный источник версии — `defaultConfig` в `usb-multitool/app/build.gradle.kts` (сейчас `versionCode = 1`, `versionName = "0.1.0"`).

- `versionCode` увеличивается на 1 при выпуске новой устанавливаемой версии, а не на каждом прогоне CI: проверочные сборки версию не меняют. Выпущенные значения `versionCode` не повторяются и не уменьшаются, иначе Android не сможет сравнить две установки.
- `versionName` следует MAJOR.MINOR.PATCH и не убывает; тег, когда теги появятся, — `v<versionName>`.
- Заголовок приложения показывает установленную `versionName` из `PackageManager`: после сайдлоада видно версию, реально стоящую на устройстве.

Стек: Kotlin 2.2.10, Jetpack Compose (BOM 2025.12.01), AGP 8.13.2, Gradle 8.13, NDK 29.0.14206865, CMake 3.22.1, Java 21 в CI. Тесты — JUnit 4, MockK, kotlinx-coroutines-test; native host-тесты собираются обычным `make`/`gcc`.

Подробности — `usb-multitool/third_party/README.md`. При распространении APK действуют обязательства GPL по предоставлению исходников.

Проект не связан с Ventoy, Tuxera, EtchDroid и другими упомянутыми проектами.
