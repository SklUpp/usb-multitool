# Требования: документация, ревью и оценка кандидатов

Дата: 2026-11-22. Статус: зафиксировано до информационного анализа и
реализации. Документ задаёт границы задачи; найденные факты и выводы — в
[feature-candidates.md](../feature-candidates.md).

## Цель

1. Обновить документацию под фактическое состояние `c5e916b`.
2. Провести комплексное независимое ревью всех правок после `a73d18e`.
3. Дать критическую информационную оценку пяти кандидатам, не выдавая
   неподтверждённые утверждения за факты.

## Обязательные требования

- R1. Документация должна отделять проверенное поведение от предположений и
  планов; ссылки на код и стандарты обязательны.
- R2. Ревью покрывает все изменения `a73d18e..HEAD`: UI/state, FAT/JNI/ext4,
  USB/SAF/files и связанные тесты. Ревьюер не правит рабочее дерево.
- R3. Каждая находка ревью получает severity, точный якорь и проверяемый
  сценарий; родитель подтверждает её до исправления.
- R4. Для каждого кандидата фиксируются: реальная ценность, зависимости,
  деструктивность, минимальный проверяемый объём и условия отказа.
- R5. Нельзя утверждать, что функция уже готова, если код выключен флагом,
  API отсутствует или поведение зависит от прошивки/вендора.
- R6. Деструктивные кандидаты не реализуются и не запускаются в этой задаче;
  достаточно требований и безопасного дизайна.
- R7. Изменения кода допускаются только для исправления подтверждённых
  ревью-дефектов; новые фичи кандидатов — отдельная задача после согласования.
- R8. Проверки: targeted unit/host tests, компиляция, `git diff --check`;
  отсутствие device-проверки указывается явно.
- R9. Итоговые документы: `progress.md`, `ui.md`, `filesystems.md`,
  `architecture.md` (при необходимости), `docs/README.md` и отдельный
  `feature-candidates.md`.

## Кандидаты: границы оценки

| № | Кандидат | Обязательное условие перед реализацией |
|---|---|---|
| 1 | S.M.A.R.T. через ATA PASS-THROUGH (16), opcode `0x85` | Только whitelisted read-only ATA-команды; capability probe и корректный разбор sense; поддержка бриджа не предполагается. |
| 2 | Быстрый детектор поддельной ёмкости по идее f3probe | Только Diagnostics, только размонтированный эксклюзивный диск, явное предупреждение о потере данных; автоматический запуск запрещён. |
| 3 | `persistence.dat` для Ventoy через `f_expand` | `FF_USE_EXPAND` сейчас `0`; нужно включить и доказать непрерывный extent, создать file-backed block device, обработать `FR_DENIED`; «гарантия 4 ГБ» запрещена. |
| 4 | Восстановление таблицы по VBR | VBR-скан только чтение; 1 MiB не считать универсальным шагом; не использовать пустой `TableInitializer.gptPlan` как готовый API; запись только после подтверждения точной геометрии. |
| 5 | SCSI UNMAP/TRIM, opcode `0x42` | Проверять VPD Block Limits/LBP, а не только LBPME; granularity брать у устройства; учитывать free-space semantics и деструктивность; отложить до отдельного стенда. |

## Вне задачи

- Реализация S.M.A.R.T., f3probe, persistence, восстановления по VBR и TRIM.
- Изменение partition/FAT write semantics ради кандидатов.
- Проверки на физическом USB, TalkBack, IME, RTL и реальном рендере.
- Push и CI-прогон не являются условием анализа; публикация — только после
  принятия результатов родителем.

## Критерии готовности

- Документы отражают `c5e916b`, включая FAT streaming, JNI-helper и UI-волну.
- Независимое ревью завершено вердиктом; подтверждённые дефекты исправлены или
  явно вынесены с причиной.
- Оценка кандидатов содержит источники и не содержит ложных «100% готово»,
  «0 рисков» и «все бриджи поддерживают».
- `feature-candidates.md` связан из индекса документации.
- Выполнены заявленные targeted-проверки; ограничения перечислены.
