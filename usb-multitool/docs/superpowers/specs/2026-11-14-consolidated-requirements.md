# USB Multitool: консолидированные требования

**Назначение:** единый контракт пользовательских требований. Исходные тексты и матрица ID сохранены в [оригиналах](2026-11-14-user-notes-originals.md), включая `New file (1).txt`. При прямом конфликте `New file (1).txt` имеет приоритет над остальными сохранёнными заметками и рабочей матрицей. Инварианты безопасности и ограничения платформы сохраняются. Матрица — рабочая интерпретация, не доказательство реализации.

Актуальный прогресс, commit SHA и проверки: [состояние проекта](2026-11-14-project-progress.md). Архитектура: [план](2026-11-12-architecture-refactor-plan.md) и [модель USB](2026-11-14-usb-interaction-state-model.md).

## Правила консолидации и доказательств

- Не реализовывать повторно уже присутствующие сценарии: сначала проверить конкретный ID, его вызовы и поведение.
- Существующий код или тест — статическое свидетельство, не доказательство полного пользовательского сценария. Для приёмки нужны сценарий и результат проверки актуальной версии; UI дополнительно требует проверки фактического экрана.
- Сохранять границы из [модели взаимодействия Android и USB](2026-11-14-usb-interaction-state-model.md): повтор неизвестной OUT-записи запрещён; цель и диапазон перепроверяются; возможная частичная запись не становится успехом; sync/readback не обещают неподконтрольную долговечность.
- Подтверждение destructive-действий, сохранение пользовательских данных и неизвестных XML/JSON-конструкций не уступают требованиям визуального упрощения.
- Запретить замену непустого каталога SAF до отдельного решения о семантике; разрешение на рискованную замену файла не разрешает удаление дерева.
- Доступ устройства к записи не проверять тестовой записью. Различать фактический writable mount, политику приложения и неизвестность; EFI-переключатель — защита приложения, не аппаратный write-protect.
- Новые зависимости, обещания автопродолжения после disconnect и перенос состояния внешнего устройства в UI не добавлять ради унификации.

## Полный перечень требований

Все требования сохраняют исходные идентификаторы и формулировки в [полной матрице](2026-11-14-user-notes-originals.md#localusb-requirements-matrixmd):

| Файлы | FILE-01–FILE-12 | Выбор раздела, доступное место, путь и иконки, RO/RW, мультивыбор, копирование и конфликты. |
| Статус операций | OPS-01–OPS-03 | Числовой прогресс и детали копирования; успешное копирование выбирает образ. |
| Ventoy | VTY-01–VTY-13 | Версии, загрузка, установка/обновление, выбор и копирование образов с USB и телефона. |
| Windows XML | WIN-01–WIN-09 | Выбор образа, генератор и импорт XML, редактирование, безопасное сохранение неизвестного, backup. |
| Global settings | GLS-01–GLS-07 | Выбор и проверка JSON, известные ключи и произвольные пары, сохранение остальных разделов, редактор. |
| Разделы | PAR-01–PAR-14 | Схема GPT/MBR, доступные действия, выбор на карте/в списке, информация, форматирование и создание. |
| Raw | RAW-01–RAW-07 | Выбор источника с USB/телефона, карта диапазонов, расчёт размера, проверка пересечений и подтверждение. |
| Диагностика | DGN-01–DGN-06 | Образ+карта, GPT backup/restore, стирание, хранение, очистка данных. |
| Безопасность и ревью | REV-01–REV-06 | Явные подтверждения, отмена/ошибка/partial, реальные данные, evidence для ID, CI и документация. |

Для каждого требования сохранить отдельный сценарий и доказательство из исходной матрицы; неопределённые поля не объявлять реализованными.

## Согласование пересекающихся заметок

1. **Названия разделов:** в «Файлы» заголовок блока разделов убрать; на экране разделов блок схемы называется «Разметка». Это заменяет противоречащие FILE-01 и PAR-01 из старой матрицы.
2. **Состояние образа Ventoy:** объединённая секция показывает «Выбранный образ», действие выбора и состояние копирования с именем и назначением. Общий статус операции сохраняет прогресс и честные ошибку/`Partial`.
3. **Ventoy download/install/update:** иконка загрузки проверяет upstream и предлагает скачать только новую версию или сообщает об отсутствии обновления; проверенную скачанную версию выделить оранжевым. Установка и обновление — разные действия; сохранение пользовательских данных при обновлении должно проверяться по коду, предупреждения и реальные риски сохраняются.
4. **Размеры и проценты:** где известны, отображать объём и процент; где процент неизвестен, отображать измеряемый объём или этап без выдуманного значения.
5. **Интерактивная карта:** это функциональный индикатор, не декоративный разделитель. `20dp` в заметках — пример, не утверждённый touch target; выбор должен оставаться доступным также через список, особенно при большом количестве разделов.
6. **GPT:** repair резервной GPT и конверсия схемы не считать эквивалентными. Не предлагать неподдержанную операцию или сохранение структуры без доказанного алгоритма и отдельного предупреждения.
7. **Поля раздела:** в «Информации о разделе» показать имя, метку, EFI, загрузочный флаг, фактический RO/RW, файловую систему и свободное место; размер и LBA оттуда убрать. В списке разделов сохранить физический размер и диапазон блоков. Границы и проверки LBA в коде обязательны.
8. **Backup image/GPT:** общая пользовательская папка допустима как вариант, её обязательность не установлена. До решения не навязывать выбор при первом старте.
9. **SAF-конфликты:** каждый конфликт файла обрабатывается отдельно; Replace файла допускается только после явного предупреждения о риске, последующая неопределённая запись даёт `Partial`. Replace непустого дерева остаётся запрещённым до отдельного решения.

**FILE multi-select implemented contract:** batch delete/download/upload pin `FilesBatchSelection` (directory + items + identity/attach/partition geometry) before picker and again before each mutation; stale pin → `FilesPickTargetInvalid`/`TargetChanged`, never retarget. Multi/dir download uses `OpenDocumentTree`; single file keeps `CreateDocument`. Conflicts: file Skip/ReplaceFile/Cancel; directory Skip/Cancel only (empty dest dir may be reused as container — not replace). Nonempty dest dir never replaced. Cancel before mutation → Cancelled; after mutationAttempted → Partial. One USB owner via `submitFilesOperation`/`filesSession`; conflict dialog parks work and releases the lock before UI. Multi rename not offered.

10. **Текст и контраст:** основной текст контрастен в светлой и тёмной теме; функциональные цветовые индикаторы RO, предупреждений и схемы сохраняются, где пользователь их прямо запросил.

## Открытые продуктовые решения

- Семантика Replace непустого каталога SAF не утверждена: до решения не удалять существующее дерево.
- Общая backup-папка image/GPT допустима, но её обязательность не установлена.
- Нельзя называть XML/JSON backup атомарным без доказательства; непредставимые конструкции не удалять молча.
